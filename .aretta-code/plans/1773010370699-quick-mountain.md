# Feature: Boogie Interpreter Bug Fixes and Optimizations

## Overview
Systematic analysis of the Rust native Boogie interpreter identified 5 bugs in bitvector operations (division by zero handling, arithmetic shift right, signed division semantics, shift masking, signed remainder) and 2 performance optimizations (variable/block name lookups). All bugs relate to SMT-LIB 2.6 bitvector theory compliance.

## Pattern Selected
| Pattern | Specification Verification Audit |
| Source | known_pattern |
| Reference | SMT-LIB 2.6 Theory of FixedSizeBitVectors |
| Rationale | Systematic comparison against authoritative spec catches semantic errors |

## Scope
### In Scope
- native/src/builtins.rs - bitvector operations (Udiv, Sdiv, Ashr, Shl, Lshr, Srem)
- native/src/lib.rs - Python-Rust interface (variable/block lookup optimization)

### Out of Scope

## High-Level Specification

**Acceptance Criteria:**
1. Given division by zero in Udiv, when executed, then return all-ones (mask) per SMT-LIB, not panic
2. Given division by zero in Sdiv, when executed, then return all-ones (mask) per SMT-LIB, not panic
3. Given negative dividend in Sdiv, when divided by positive divisor, then use truncated division (toward zero), not floor division
4. Given any bit width in Ashr, when right shifting negative value, then correctly sign-extend for that bit width
5. Given shift amount >= bit width in Shl/Lshr/Ashr, when executed, then use shift % bits, not shift & (bits-1)
6. Given division by zero in Srem, when executed, then return dividend, not 0
7. Given variable name lookup in execute(), when called, then O(1) HashMap lookup, not O(n) linear scan

**Examples:**
- Success: `udiv(0x12345678, 0, 32)` returns `0xFFFFFFFF`
- Success: `sdiv(-8, 3, 32)` returns `-2` (truncated), not `-3` (floor)
- Success: `ashr(0x8000000000000000, 1, 64)` returns `0xC000000000000000`
- Success: `shl(1, 32, 32)` returns `1` (shift 32 mod 32 = 0)
- Success: `srem(5, 0, 32)` returns `5`

## Flow Pseudocode

### Bug 1: Udiv Division by Zero

```rust
BuiltinFn::Udiv { bits } => {
    let m = mask(bits) as u64;
    let a_masked = a as u64 & m;
    let b_masked = b as u64 & m;
    // pf:requires:udiv.operands - a, b are valid i64
    // pf:ensures:udiv.zero_divisor - returns all-ones when b_masked == 0
    if b_masked == 0 {
        return (m as i64, false);  // all-ones, not panic
    }
    let result = a_masked / b_masked;
    // pf:ensures:udiv.result - masked to bit width
    (result as i64 & mask(bits), false)
}
```

### Bug 2: Sdiv Division Semantics

```rust
BuiltinFn::Sdiv { bits } => {
    let sx = to_signed(a, bits);
    let sy = to_signed(b, bits);
    let m = mask(bits);
    // pf:ensures:sdiv.zero_divisor - returns all-ones when sy == 0
    if sy == 0 {
        return (m, false);  // all-ones per SMT-LIB
    }
    // pf:ensures:sdiv.truncated - Rust's / is already truncated division
    // No change needed - Rust division truncates toward zero
    (to_signed(sx / sy, bits) & m, false)
}
```

### Bug 3: Ashr Generalization

```rust
BuiltinFn::Ashr { bits } => {
    let m = mask(bits);
    let v = a & m;
    // pf:ensures:ashr.shift_mask - shift amount is b mod bits
    let shift = (b as u32) % (bits as u32);
    let sign_bit = 1i64 << (bits - 1);
    // pf:ensures:ashr.sign_extend - high bits filled with sign bit copies
    if v & sign_bit != 0 {
        // Negative value - sign extend
        let fill = if shift == 0 { 0 } else { (!0i64) << (bits as i64 - shift as i64) };
        ((v >> shift) | (fill & m), false)
    } else {
        // Positive value - zero extend
        ((v >> shift) & m, false)
    }
}
```

### Bug 4: Shift Amount Masking

```rust
// Current (WRONG): let shift = (b as u32) & (bits as u32 - 1);
// Correct: let shift = (b as u32) % (bits as u32);
// 
// Difference: For bits=32, (b & 31) and (b % 32) are equivalent
// But the semantic intent is modulo, and for consistency with SMT-LIB
// we should use modulo explicitly.
// 
// However, for power-of-2 bit widths (8, 16, 32, 64), they ARE equivalent.
// This is actually NOT a bug for the supported bit widths.
// Keeping as potential future issue if non-power-of-2 widths are added.
```

### Bug 5: Srem Division by Zero

```rust
BuiltinFn::Srem { bits } => {
    let sx = to_signed(a, bits);
    let sy = to_signed(b, bits);
    let m = mask(bits);
    // pf:ensures:srem.zero_divisor - returns dividend when sy == 0
    if sy == 0 {
        return (sx & m, false);  // return dividend, not 0
    }
    let q = sx / sy;  // truncated division
    let r = sx - q * sy;
    (r & m, false)
}
```

## Key Functions

### exec_binary (builtins.rs)
Primary implementation of bitvector operations. Contains all 5 bugs.

| Operation | Current Issue | SMT-LIB Spec | Fix |
|-----------|--------------|--------------|-----|
| Udiv | Panics on b=0 | Return all-ones | Add zero check |
| Sdiv | Panics on b=0 | Return all-ones | Add zero check |
| Ashr | Only handles 32/64 | Generic for any width | Generalize |
| Shl/Lshr | Uses b & (bits-1) | Uses b mod bits | Actually equivalent for power-of-2 |
| Srem | Returns 0 on b=0 | Return dividend | Fix zero check |

## Decisions Made

| Question | Decision | Rationale |
|----------|----------|-----------|
| Shift masking: bits-1 vs mod bits | Keep bits-1 | Equivalent for power-of-2 widths |
| Division by zero result | All-ones (mask) | SMT-LIB 2.6 specification |
| Srem by zero result | Return dividend | SMT-LIB bvsrem semantics |

## Failure Modes

| Failure | Response | Recovery |
|---------|----------|----------|
| Division by zero | Return all-ones | Defined behavior, no panic |
| Shift amount overflow | Mask to bit width | Modulo reduction |
| Invalid bit width | Panic (debug only) | Should never happen in production |
