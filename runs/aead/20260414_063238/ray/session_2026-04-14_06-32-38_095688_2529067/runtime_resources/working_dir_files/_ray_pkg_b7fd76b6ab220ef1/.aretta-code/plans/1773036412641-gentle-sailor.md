# Feature: Verified Boogie Interpreter

## Overview

Formally verify that both Python and Rust implementations of the Boogie IVL interpreter have correct operational semantics, matching the SMT-LIB 2.6 FixedSizeBitVectors theory specification. Uses Kani for Rust bounded model checking and Crosshair for Python symbolic execution, with a shared YAML spec as single source of truth.

## Pattern Selected

| Aspect | Value |
|--------|-------|
| Pattern | Formal Verification with Shared Spec |
| Source | researched |
| Reference | SMT-LIB 2.6: https://smtlib.cs.uiowa.edu/theories-FixedSizeBitVectors.shtml |
| Tools | Kani (Rust), Crosshair (Python) |
| Rationale | SMT-LIB 2.6 is the authoritative standard; Kani provides complete bounded verification; Crosshair enables Python symbolic execution; both can verify against shared spec |

## Scope

### In Scope
- All bitvector builtins (native/src/builtins.rs, utils/bitops.py)
- Expression evaluation (VM::eval in vm.rs, _eval in interpreter.py)
- Statement execution (VM::execute_stmt in vm.rs, _execute_statement in interpreter.py)
- Memory map operations (load/store)
- Binary operators (BinOp enum)

### Out of Scope
- Parsing (boogie.lark, boogie_parser.py) - separate verification task
- Lowering (lowering.rs) - separate verification task
- Trace accumulation - observational, doesn't affect semantics
- External I/O (read.cross_product, write.cross_product)
- Quantified assume pattern matching (memset/memcpy) - separate task

## High-Level Specification

**Acceptance Criteria:**

1. Given any bitvector operation with valid inputs, when executed in Python or Rust, then result matches SMT-LIB 2.6 semantics exactly
2. Given division by zero (bvudiv/bvsdiv/bvurem/bvsrem), when executed, then returns SMT-LIB defined value:
   - bvudiv(x, 0) = all-ones (2^m - 1)
   - bvsdiv(x, 0) = all-ones (via bvudiv)
   - bvurem(x, 0) = x (dividend)
   - bvsrem(x, 0) = x (via bvurem)
3. Given any shift amount >= bit width, when executed, then returns SMT-LIB defined value (0 or sign-fill)
4. Given bvsdiv with negative operands, when executed, then uses truncated division (toward zero), NOT floor division
5. Given any expression in the Boogie AST, when evaluated in Python, then result equals Rust VM evaluation
6. Given any sequence of statements, when executed in Python, then final environment equals Rust VM environment
7. Kani verification completes with VERIFICATION SUCCESSFUL for all harnesses
8. Crosshair verification finds no counterexamples for all contracts

**Examples:**

| Scenario | Input | Expected Output |
|----------|-------|-----------------|
| Division by zero | bvudiv(0x12345678, 0) @ 32-bit | 0xFFFFFFFF |
| Signed division truncation | bvsdiv(-8, 3) @ 32-bit | -2 (not -3) |
| Arithmetic shift right | bvashr(0x80, 1) @ 8-bit | 0xC0 |
| Shift by bit width | bvshl(1, 32) @ 32-bit | 0 (per SMT-LIB) |
| Sign extension | sext(0x80, 8->32) | 0xFFFFFF80 |

## Flow Pseudocode

```
VERIFICATION ARCHITECTURE
=========================

LAYER 1: SHARED SPEC
────────────────────
spec = load_yaml(".aretta-code/specs/smtlib-bv.spec.yaml")
# pf:requires:spec.valid YAML with SMT-LIB operations

for op in spec.operations:
    # pf:ensures:op.semantics matches SMT-LIB 2.6
    validate_against_smtlib(op)


LAYER 2: RUST VERIFICATION (Kani)
─────────────────────────────────
# For each function: builtins.rs, vm.rs

#[kani::requires(bits in {8, 16, 32, 64})]
#[kani::ensures(|result| b == 0 || result.0 == expected)]
#[kani::ensures(|result| b != 0 || result.0 == mask(bits))]
fn exec_binary(fn_id: BuiltinFn, a: i64, b: i64) -> (i64, bool)
    # pf:never:panic_on_zero No panic when b == 0

#[kani::proof_for_contract(exec_binary)]
fn verify_exec_binary():
    let fn_id: BuiltinFn = kani::any()
    let a: i64 = kani::any()
    let b: i64 = kani::any()
    # Kani explores ALL possible inputs
    exec_binary(fn_id, a, b)
    # If contract holds for all paths -> VERIFICATION SUCCESSFUL


LAYER 3: PYTHON VERIFICATION (Crosshair)
────────────────────────────────────────
def add_fn(bits: int):
    """
    pre: bits in (8, 16, 32, 64)
    """
    mask = (1 << bits) - 1
    def _add(x: int, y: int) -> int:
        # pf:requires:inputs_bounded 0 <= x < 2^64 and 0 <= y < 2^64
        assert 0 <= x < (1 << 64)
        assert 0 <= y < (1 << 64)
        
        result = ((x & mask) + (y & mask)) & mask
        
        # pf:ensures:result_bounded 0 <= result < 2^bits
        assert 0 <= result < (1 << bits)
        # pf:ensures:matches_smtlib result == nat2bv[bits](bv2nat(x) + bv2nat(y))
        
        return result
    return _add

# Run: crosshair check utils/bitops.py
# Crosshair symbolically executes, finds counterexamples if contract violated


LAYER 4: CROSS-VALIDATION
─────────────────────────
def verify_equivalence():
    """
    Prove: forall op, inputs. python_impl(op, inputs) == rust_impl(op, inputs)
    """
    for op in ALL_BITVECTOR_OPS:
        for bits in [8, 16, 32, 64]:
            for a in symbolic_range(bits):
                for b in symbolic_range(bits):
                    py_result = python_fn_map[op](bits)(a, b)
                    rs_result = rust_exec_binary(op, bits, a, b)
                    # pf:ensures:equivalence py_result == rs_result
                    assert py_result == rs_result, f"Mismatch: {op}({a}, {b}) @ {bits}"


ERROR PATHS
───────────
• Kani counterexample → Rust violates spec → fix builtins.rs/vm.rs
• Crosshair counterexample → Python violates spec → fix bitops.py/interpreter.py
• Cross-validation mismatch → implementations diverge → align to SMT-LIB
```

## Key Functions

### exec_binary (builtins.rs)

```rust
// TIER 2: Detailed specification for security-critical bitvector operations

// pf:function_signature:exec_binary
// fn exec_binary(fn_id: BuiltinFn, a: i64, b: i64) -> (i64, bool)

// DIVISION BY ZERO HANDLING
// ─────────────────────────
// pf:requires:valid_fn_id fn_id is a valid BuiltinFn variant
// pf:requires:valid_bits bits field (if present) in {8, 16, 32, 64}

// Udiv
// pf:ensures:udiv.zero_divisor b == 0 => result.0 == mask(bits)
// pf:ensures:udiv.normal b != 0 => result.0 == (a & mask) / (b & mask)
// pf:never:udiv.panic NEVER panic when b == 0

// Sdiv
// pf:ensures:sdiv.zero_divisor sy == 0 => result.0 == mask(bits)
// pf:ensures:sdiv.truncated Uses truncated division (toward zero)
// pf:never:sdiv.floor_division NEVER use floor division semantics
// pf:never:sdiv.panic NEVER panic when sy == 0

// Srem
// pf:ensures:srem.zero_divisor sy == 0 => result.0 == sx (dividend)
// pf:ensures:srem.sign_follows_dividend sign(result) == sign(sx)
// pf:never:srem.return_zero NEVER return 0 when sy == 0

// SHIFT OPERATIONS
// ────────────────
// pf:ensures:shl.overflow shift >= bits => result.0 == 0
// pf:ensures:ashr.sign_extension negative value => high bits filled with 1s
// pf:ensures:ashr.generic_width works for ALL bit widths, not just 32/64
// pf:never:ashr.hardcoded_widths NEVER have separate paths only for 32/64
```

## Decisions Made

| Question | Decision | Rationale |
|----------|----------|-----------|
| Reference spec | SMT-LIB 2.6 FixedSizeBitVectors | Authoritative standard, used by Z3/CVC5 |
| Rust verification tool | Kani | Complete bounded model checking, AWS-backed |
| Python verification tool | Crosshair | Symbolic execution with Z3, pytest integration |
| Shared spec format | YAML | Human-readable, parseable by both languages |
| Division by zero semantics | Return defined value (not panic) | SMT-LIB 2.6 defines bvudiv(x,0) = all-ones |
| Signed division | Truncated (toward zero) | SMT-LIB bvsdiv uses truncated, not floor |
| Shift amount masking | No masking (SMT-LIB) | SMT-LIB shifts use full value, not modulo |

## Failure Modes

| Failure | Response | Recovery |
|---------|----------|----------|
| Kani counterexample | CI fails, shows concrete inputs | Fix Rust code to match spec |
| Crosshair counterexample | CI fails, shows concrete inputs | Fix Python code to match spec |
| Cross-validation mismatch | CI fails, shows divergent op | Align both to SMT-LIB |
| Kani timeout | Increase unwind bound | Add #[kani::unwind(N)] |
| Crosshair timeout | Increase per_condition_timeout | Split large functions |
| Spec ambiguity | Consult SMT-LIB docs | Update spec with clarification |

## Kani Integration

**Cargo.toml additions:**
```toml
[lints.rust]
unexpected_cfgs = { level = "warn", check-cfg = ['cfg(kani)'] }

[package.metadata.kani.flags]
default-unwind = "10"
```

**Running verification:**
```bash
# Install Kani
cargo install --locked kani-verifier
cargo kani setup

# Run all proofs
cd native
cargo kani -Z function-contracts

# Run specific harness
cargo kani -Z function-contracts --harness verify_udiv_zero_divisor
```

## Crosshair Integration

**Installation:**
```bash
pip install crosshair-tool icontract
```

**Running verification:**
```bash
# Watch mode (development)
crosshair watch utils/bitops.py

# CI mode
crosshair check --analysis_kind=asserts utils/bitops.py python/interpreter.py

# With timeout
crosshair check --per_condition_timeout=30 utils/bitops.py
```

**Pytest integration:**
```python
# test_crosshair.py
from hypothesis import given, settings
from hypothesis import strategies as st

@settings(backend='crosshair')
@given(a=st.integers(), b=st.integers())
def test_add_commutative(a: int, b: int):
    add = add_fn(32)
    assert add(a, b) == add(b, a)
```
